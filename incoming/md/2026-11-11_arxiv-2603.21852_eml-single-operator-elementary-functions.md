# EML: all elementary functions from a single operator

*One two-input gate plus the constant 1 rebuilds the whole scientific calculator. This page explains how it works, how big the circuits get, where the NAND analogy breaks, and how far the symbolic-regression claim goes.*

## 1. The claim

In digital logic, one two-input gate (NAND, the Sheffer stroke) wired into trees builds any Boolean circuit. Continuous mathematics has never had an equivalent. A calculator needs separate buttons for +, ×, exp, ln, sin, √ and so on.

The paper says one binary operator is enough:

$$\mathrm{eml}(x, y) = e^{x} - \ln y$$

With the constant 1, it generates everything on a scientific calculator: the four arithmetic operations, powers and roots, exp, ln, the trig functions, and the constants e, π and i. "EML" stands for Exp-Minus-Log.

## 2. How it works: bootstrapping from one gate

You can watch the gate split into its parts. Each line uses only things built on earlier lines.

| Step | Construction | Why it works |
|---|---|---|
| **e** | eml(1, 1) | e¹ − ln 1 = e − 0 |
| **exp(x)** | eml(x, 1) | ln 1 = 0, so the log half drops out |
| **ln(x)** | eml(1, eml(eml(1, x), 1)) | Inner: e − ln x. Then exp of that: eᵉ/x. Outer: e − ln(eᵉ/x) = **ln x** |
| **0** | ln(1) | from the line above |
| **x − y** | eml(ln x, exp y) | e^(ln x) − ln(eʸ) = x − y |
| **−y, x + y** | 0 − y, then x − (−y) | subtraction is enough for both |
| **x·y, x/y, xʸ** | exp(ln x + ln y), and so on | the slide-rule identity |
| **−1, then i and π** | ln(−1) = iπ | requires complex numbers |
| **sin, cos** | Euler: cos x = (e^(ix) + e^(−ix))/2 | once i and exp exist |

The key step is **ln(x)**: three nested gates arranged so the exp part cancels itself. Once exp and ln can be isolated, the rest follows from identities that are centuries old.

**What is new and what isn't.** Mathematicians already knew that exp, ln and arithmetic together generate the elementary functions (the exp-log representation). The new step is putting **exp, log and subtraction into one binary operation**, chosen so that it can be taken apart again.

## 3. Why the tree structure matters

Every EML expression follows the grammar

$$S \to 1 \mid \mathrm{eml}(S, S)$$

so every formula is a full binary tree of identical gates, with leaves that are 1 or an input variable. The number of tree shapes with n gates is the Catalan number Cₙ, which grows roughly as 4ⁿ.

- **Small trees can be searched exhaustively.** That is how the operator was found (section 7).
- **The search space is uniform.** One trainable architecture covers every elementary formula, which is the basis of the symbolic-regression result (section 6).

**Analogy:** a standard-cell library with exactly one cell. Synthesis becomes a pure question of wiring, with no cell selection. Where it fails: real cell libraries are chosen to make circuits *small*. EML makes them uniform but large.

## 4. How big the circuits get

Two things stand out:

- **Multiplication is cheaper than addition.** The gate is built from exp and log, so it works naturally in multiplicative terms. Addition has to take a detour.
- **Entries marked ">" are only lower bounds.** The exhaustive search stopped at K = 9, so the optimal sizes of π, i and the trig functions are unknown. This is a NAND-count problem with no synthesis tool yet. The author calls the compiler unoptimized.

## 5. Where the NAND analogy breaks

The NAND analogy is accurate as a statement about *generation*. It fails in four places.

1. **The gate is not cheap.** NAND is about four transistors. Each EML node evaluates a transcendental exp and log, and x + y takes nine of them. This is a result about **representation, not computation**. Nobody will build a calculator this way.

2. **Values leave the "logic levels."** Boolean circuits stay in {0, 1}. EML needs **complex intermediate values** even for real results, because −1, i and π come from ln(−1). The author says a purely real continuous Sheffer operator "seems impossible," but this is not proven.

3. **Branch cuts and infinities are load-bearing.**
   - The three-gate ln construction computes ln z as e − log(eᵉ/z). On the negative real axis this **jumps by 2πi** relative to the principal branch, which flips the sign of anything built from i. The paper offers two fixes: redefine the EML branch so ln follows the principal branch, or correct the sign of i by hand.
   - The constructions rely on **ln 0 = −∞ and e^(−∞) = 0**. IEEE 754 arithmetic (C's math.h, NumPy, PyTorch) supports this. Plain Python and Julia raise errors instead. Mathematica works but overflows into an extended range.
   - **Lean 4 cannot formalize the chain as written**, because Mathlib defines Complex.log 0 = 0 as a default value. See [[lean-proof-assistant]] on how such conventions affect what a formal proof certifies.
   - Numerically, intermediate values such as eᵉ/x and eʸ overflow easily. In double precision e^y overflows once y is above about 709. The result is exact in exact arithmetic but fragile in floating point.

4. **NAND needs no constant; EML needs the 1.** NAND can make its own constants from any input. EML cannot produce 0 or 1 from arbitrary inputs, so 1 has to be supplied as a terminal. A constant-free EML-type operator is listed as an open question.

## 6. Symbolic regression: what the training results show

**Setup.** Each input slot of each gate is a linear mix α + βx + γf, where f is the output of the child gate. Setting (α, β, γ) to (1,0,0), (0,1,0) or (0,0,1) selects 1, x or the child. A depth-n "master formula" has 5·2ⁿ − 6 parameters, so depth 2 has 14. Training uses Adam in complex128 PyTorch, then a "hardening" phase pushes weights toward 0 or 1, and then the weights are snapped to exact values. A small demo fit a depth-3 tree to ln x data with Mathematica's NMinimize. Rounding the weights recovered ln x exactly, including outside the training range.

**Results from random initialization (1000+ runs):**

| Tree depth | Exact recovery |
|---|---|
| 2 | 100% |
| 3–4 | ~25% |
| 5 | < 1% |
| 6 | 0 of 448 |

**The key detail.** Starting from **slightly perturbed weights of the correct tree**, training converged back to the exact weights in **100% of runs, even at depths 5 and 6**. The correct solutions are stable minima; what fails at depth is finding the right basin. In hardware terms, the circuit is correct and stable, but the search has no good starting point. Successful runs reach MSE ≈ 10⁻³² (machine epsilon squared), so recovered formulas are exact, not approximations.

**Failure modes reported:** overflow from nested exponentials, NaNs from complex arithmetic, and basins of attraction that get harder to find as depth grows. Training needed clamping of exp arguments and careful handling of real and imaginary parts.

**Context.** Earlier symbolic-regression systems that use differentiable networks with mixed operator sets (EQL networks, PySR, AI Feynman) hit similar scaling limits. These results don't show whether a uniform EML basis beats a mixed operator set at realistic depths.

## 7. How the operator was found, and its relatives

**Search procedure.** The author used ablation and bootstrapping. Start from a base set such as {1, eml}, search for an expression equal to one target function, add it to the base, and repeat until every target is covered. Candidate identities were checked **numerically**: transcendental test values (Euler–Mascheroni γ, the Glaisher–Kinkelin constant A) were substituted and matched with an inverse symbolic calculator. The author calls this a heuristic filter whose reliability depends on Schanuel's conjecture. Formal verification is deferred to the Supplementary Information (not read here).

**Relatives found:**

- **EDL:** eˣ / ln y, with constant e
- **−EML:** ln x − eʸ, with constant −∞
- **A ternary candidate:** T(x, y, z) = (eˣ / ln x) · (ln z / eʸ). Note that T(x, x, x) = 1, so it may produce its own constant and fix the NAND gap in section 5. The author marks it "in preparation."

## 8. Verdict

- **The mathematical result holds up** as a clean "Sheffer stroke for calculus." The constructions can be checked by hand, as section 2 shows. It comes with three real conditions: it needs the constant 1, it needs complex intermediate values, and it depends on branch and infinity conventions. The completeness argument is a proof sketch, and formal verification is not in the main text.
- **It says nothing new about the functions themselves.** It is a clever choice of basis, not a new theorem about elementary functions.
- **No computational advantage.** EML trees are far more expensive to evaluate than direct arithmetic and are numerically fragile.
- **The symbolic-regression side is a proof of concept.** Exact recovery is reliable only to depth 2, partial at depths 3–4, and fails beyond that without a good initialization.
- **Most interesting follow-up:** the ternary operator T, which might remove the need for a constant. Also worth watching: whether a better search or initialization can push exact recovery past depth 4.
